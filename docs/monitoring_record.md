# 모니터링 영상 녹화 (미결정)

> 구현 여부 미정. 현재 기능 안정화 후 검토.

## 배경

현재 모니터링은 **라이브 스트리밍 전용** (Family가 보고 있을 때만 의미 있음).
녹화 기능이 추가되면 Family가 없을 때 발생한 상황도 사후 확인 가능.

**주요 활용 시나리오**
- 낙상 등 이상 상황 사후 확인
- 수면/생활 패턴 파악
- "아까 무슨 일 있었나?" — 실시간 모니터링 못 한 경우 리뷰

---

## 용량 문제 (핵심 제약)

SM-T500 (Galaxy Tab A7) 내장 저장공간: **32GB**

| 해상도 | 용량/시간 | 하루 24시간 |
|--------|-----------|-------------|
| 1080p  | ~2 GB     | ~48 GB      |
| 720p   | ~1 GB     | ~24 GB      |
| 480p   | ~500 MB   | ~12 GB      |
| 360p   | ~250 MB   | ~6 GB       |

→ **상시 녹화는 현실적으로 불가** (OS/앱 포함 시 여유 공간 15~20GB 수준)

### 현실적인 대안: 모션 감지 클립만 저장

움직임 감지 시 **30~60초 클립**만 저장:
- 실제 이벤트는 하루 수십 건 수준
- 360p 기준 클립당 ~2MB → 하루 50건 = 100MB 이하
- 로컬 보존 7일 = ~700MB → **완전히 현실적**

## 아키텍처 (구현 시)

```
[Senior 태블릿]
Foreground Service (CctvRecordService)
├── VideoSink → ML Kit MotionDetector
│   └── 모션 감지 → MediaRecorder 시작 (30~60초 클립)
│       └── 클립 저장: filesDir/cctv/{timestamp}.mp4
│
├── 로컬 순환 삭제: 7일 초과 파일 자동 제거
│
└── [선택] Firebase Storage 업로드
    └── families/{fid}/cctv/{deviceId}/{timestamp}.mp4
```

**카메라 충돌 방지**: MonitoringSession이 카메라 사용 중일 때는 CctvRecordService가 같은 VideoSink를 공유 (별도 카메라 인스턴스 X)

---

## 비용/법적

- Firebase Storage 업로드 시 비용 발생 (영상 클립은 사진보다 큼) → 로컬 전용으로 시작하는 게 안전
- **한국 개인정보보호법**: 녹화 사실을 시니어에게 고지해야 함 (가족 동의 하에 사용하는 제품 특성상 완화 가능)
- 접근 제어: Family 앱 Firebase Auth 필수, Storage Rules로 가족 단위 격리

---

## 현재 코드 재활용 가능한 부분

| 기존 코드 | 재활용 방법 |
|-----------|-------------|
| `MonitoringSession` VideoSink | 모션 감지 입력 소스 |
| `ML Kit FaceDetector` | MotionDetector로 교체 또는 병행 |
| `performFullReset()` | 녹화 파일 + Storage 전부 삭제 포함 |

## 결론

| 방식 | 실현 가능성 | 비용 | 복잡도 |
|------|------------|------|--------|
| 상시 녹화 (로컬) | ❌ 용량 부족 | 없음 | 중 |
| 상시 녹화 (클라우드) | ❌ 비용 과다 | 높음 | 높음 |
| 모션 감지 클립 (로컬만) | ✅ | 없음 | 중 |
| 모션 감지 클립 (클라우드 선택적) | ✅ | 낮음 | 높음 |

**추천 방향 (구현 시)**: 로컬 전용 모션 감지 클립 → Family 앱에서 Wi-Fi 연결 시 조회/다운로드
